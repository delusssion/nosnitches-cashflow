# Методика расчёта денежных потоков

Главный документ для реализации движка. Входные и выходные форматы — [CONTRACT.md](CONTRACT.md), гипотезы H1–H9 — там же. Открытые вопросы — [QUESTIONS.md](QUESTIONS.md), аномалии данных — [DATA_QUALITY.md](DATA_QUALITY.md).
Эталонная реализация этой методики — `analytics/reference/cf_reference.py`: каждый пункт ниже соответствует блоку кода с тем же смыслом. Флаги гипотез в коде называются по номеру: `H1_RGM_EQUAL_SHARES`, `H6_REPORT_DATE_IS_PAST`, …

Обозначения: $T_0$ — дата расчёта (`report_dttm`), $T_m$ — дата погашения (`maturity_dttm`), $B$ — остаток тела со знаком сделки (`current_principal_amt`; депозит $B<0$), $r$ — годовая ставка в долях, $\tau(d_1, d_2)$ — доля года по конвенции сделки.

## 2. Построение дат

### 2.1 Источники дат

Для каждого потока строится полный список дат (прошлых и будущих), затем от него отрезается будущее (§2.4).

| Поток | Источник по приоритету |
|---|---|
| Проценты | явный список `interest_payment` → правило `interest_payment_rule_*` → правило тела `regular_payment_rule_*` (если не ENDDATE) → даты явного графика тела → нет дат; **плюс всегда** $T_m$ |
| Тело, ANN / RGM | правило `regular_payment_rule_*` → даты процентов; плюс $T_m$. ENDDATE — только $T_m$ |
| Тело, SIMPLE | явный график `principal_payment` (будущие даты) → только $T_m$ |
| Пересмотр ставки | явный список `repricing_dttm_schedule` ∪ правило `repricing_rule_*` |
| Субсидия | правило `sub_payment_rule_*`, плюс $T_m$; пересмотр — `sub_repricing_rule_*` |

Явные списки сортируются, дубли убираются; в явном графике тела суммы в одну дату складываются.

### 2.2 Правило «начало + период»

Даты правила — все $d_k$ из интервала $(s, T_m]$, где $s$ — начало правила:

- период `<N>M`: $d_k$ — дата в месяце $\text{month}(s) + kN$, $k = 0, 1, \dots$; число месяца — `day_num`, если задан, иначе число из $s$; `day_num = -1` — последний день месяца; если в месяце нет такого числа (30 февраля, 31 апреля) — последний день месяца;
- период `<N>D`: $d_k = s + kN$ дней, $k \ge 1$;
- `ENDDATE` или пусто — дат нет, остаётся только $T_m$.

Пример (сделка 23, `day_num = 30`, 1M с 2022-01-20): 2022-01-30, 2022-02-28, 2022-03-30, …
Пример (сделка 30, 45D с 2022-08-01): 2022-09-15, 2022-10-30, 2022-12-14, затем $T_m$ = 2023-01-01.

### 2.3 Дата погашения

$T_m$ всегда последняя дата тела и процентов, даже если не попадает в правило (сделка 1: платежи 22-го, погашение 15.06.2050 — последний период 24 дня). Даты правил позже $T_m$ отбрасываются. Выходные и праздники не переносим (H8).

### 2.4 Что считается будущим

В выход попадают события с $d > T_0$; событие ровно в дату расчёта — прошлое (H6). Начало первого будущего периода начисления процентов — последняя дата процентов $\le T_0$, а если её нет — `deal_dttm`. Пример: у сделки 44 дата процентов 2022-08-31 = $T_0$ — период начинается 2022-08-31; у сделки 15 (выдана 16.08.2022, проценты 14-го) — с 2022-08-16.

## 3. Конвенции дней

$$\tau_{\text{ACT/365}}(d_1, d_2) = \frac{d_2 - d_1}{365}$$

$$\tau_{\text{ACT/ACT ISDA}}(d_1, d_2) = \sum_{y} \frac{\#\{\text{дней периода в году } y\}}{\text{365 или 366}}$$

Период режется по границам календарных лет. ACT/ACT без уточнения = ACT/ACT ISDA (H5).

**Пример с високосным годом:** 15.12.2023 → 15.01.2024, 31 день.

| Конвенция | Расчёт | $\tau$ |
|---|---|---|
| ACT/365 | $31/365$ | 0,0849315 |
| ACT/ACT ISDA | $17/365 + 14/366$ (17 дней 2023 года, 14 дней 2024) | 0,0848267 |

На сделке 1 разница конвенций за весь срок — ≈ 14 224,63 ₽ процентов ([EXCEL_ERRORS.md](EXCEL_ERRORS.md)).

## 4. Начисление процентов

### 4.1 По отрезкам

Период начисления $(a, b]$ режется на отрезки $j$ всеми событиями, при которых меняется остаток (погашение тела) или ставка (пересмотр):

$$I = \sum_j B_j \cdot r_j \cdot \tau_j ,$$

$B_j$ — остаток на отрезке (со знаком сделки), $r_j$ — ставка на отрезке, $\tau_j$ — доля года отрезка по конвенции сделки. Погашение тела в дату $d$ уменьшает остаток начиная с $d$; новая ставка пересмотра в дату $d$ действует начиная с $d$. Погашение в дату выплаты процентов $b$ на этот период не влияет.

### 4.2 Проценты до даты расчёта

Проценты, накопленные с начала периода $a < T_0$ до $T_0$, входят в первый будущий `interest_payment` (контракт). Если задано `accrued_interest` — берём его как накопленное на $T_0$ (со знаком сделки) и начисляем дальше с $T_0$ (флаг `Q13_ACCRUED_FROM_FIELD`, сделки 36–40). Иначе начисляем с $a$ по формуле §4.1, остаток на $[a, T_0)$ — `current_principal_amt`, ставка — по датам фиксинга того времени.

Пример (сделка 1): период 22.08.2022 → 22.09.2022, $I_1 = 3\,646\,037{,}89 \cdot 0{,}075 \cdot \tfrac{31}{365} = 23\,224{,}76$ ₽.

### 4.3 Досрочное закрытие тела

Если тело погашено полностью в дату, которая не является датой процентов, проценты за хвост периода платятся в эту же дату (событие `interest_payment` перед `close_payment`).

## 5. Алгоритмы по discriminator

Общий цикл по будущим датам событий $p_1 < p_2 < \dots$ (объединение дат процентов, тела, пересмотров, субсидии):

```
cursor ← T0;  accrued ← проценты до T0 (§4.2)
для каждой даты p:
    accrued += B · r · τ(cursor, p);  cursor ← p          # отрезок [cursor, p)
    если p — пересмотр:      r ← ставка(p); событие repricing        (§6)
    если p — дата процентов: событие interest_payment(accrued); accrued ← 0
    если p — дата субсидии:  событие sub_payment                     (§7)
    если p — дата тела:      P ← тело(p) по алгоритму ниже
                             если p последняя: close_payment(B), B ← 0
                             иначе principal_payment(P), B ← B − P
```

Погашение не может превышать остаток: $|P| \le |B|$.

### 5.1 ANN — аннуитет (H7)

Платёж считается от остатка на дату расчёта и пересчитывается после каждого пересмотра ставки:

$$A = B \cdot \frac{i}{1 - (1+i)^{-n}}, \qquad i = r \cdot \frac{m}{12},$$

$n$ — число оставшихся дат тела, $m$ — длина периода тела в месяцах (`1M` → 1; `<N>D` → $N \cdot 12/365$). Проценты периода — по фактическим дням (§4); тело $P_k = A - I_k$. Последний платёж — `close_payment` на весь остаток: при неравных периодах $\sum P_k \ne B$, и без закрытия остаётся долг (у экспертов — 15 420,45 ₽).

```
A ← annuity(B, r, m, n)
в дату тела p:   P ← A − I(p);  если p последняя — close_payment(B)
после пересмотра в p:  A ← annuity(B, r_new, m, число дат тела > p)
```

Контрольное число: сделка 1, ACT/ACT ISDA — проценты за срок 5 051 623,47 ₽.

### 5.2 RGM — равными долями (H1)

$$P = \frac{B(T_0)}{n},$$

$n$ — число оставшихся дат тела. Проценты начисляются на убывающий остаток (§4). Последний платёж — `close_payment` на остаток (убирает копейки округления). Пересмотр ставки долю тела не меняет.

```
P ← B / n
в дату тела p:   если p последняя — close_payment(B), иначе principal_payment(P)
```

### 5.3 SIMPLE — по графику или в конце

- Есть `principal_payment`: платим будущие суммы графика (даты $> T_0$), но не больше остатка. В $T_m$ — `close_payment` на весь остаток. Если сумма будущего графика $\ne B$ — разница уходит в `close_payment` и пишется warning `PRINCIPAL_SUM_MISMATCH` (H9). Сделка 54: график 850 085,26 из 9 020 721,21 — 8 170 635,95 гасится в 2029-10-11.
- Нет графика (ENDDATE или пусто): всё тело — `close_payment` в $T_m$.

```
для p из графика (p > T0):  P ← min(сумма(p), |B|);  principal_payment(P)
в T_m:                      close_payment(B)
```

## 6. Плавающая ставка

### 6.1 Формула (H2)

$$r(t) = \min\Big(\text{cap},\ \max\big(\text{floor},\ \text{Ind}(t_{\text{fix}}) + \text{margin}\big)\Big),$$

margin = `interest_rate` (или значение из `repricing_dttm_rate_schedule_fixed`, действующее на $t$). Пустые cap / floor не ограничивают.

### 6.2 Дата фиксинга

$t_{\text{fix}}$ — последняя дата пересмотра $\le t$, но не раньше `deal_dttm`. Пересмотры до даты расчёта определяют ставку на $T_0$; события `repricing` выводятся только для дат $T_0 < d < T_m$. FLOAT без правила и дат пересмотра: ставка фиксируется на `deal_dttm` и не меняется (флаг `Q14_FLOAT_WITHOUT_REPRICING_FIX_AT_DEAL`, сделки 25, 34, 36, 55).

### 6.3 Индикатор и прогноз

$\text{Ind}(d)$ — ключевая ставка ЦБ (`testdata/rates/key_rate.csv`), ступенчатая функция: значение действует с даты до следующей даты. Лаг: `indicator_lag_cd = -1M` → берём $\text{Ind}(d - 1\text{ месяц})$.

Будущее (H3): для $d > T_0$ значение $\text{Ind}(T_0) + \Delta$, где $\Delta$ — сдвиг сценария; в спринте 2 $\Delta = 0$ (`H3_FORECAST_SHIFT`). На 31.08.2022 ключевая ставка 8 % — она действует для всех будущих пересмотров. В спринте 3 сюда подключаются кривые команды 2.

Пример (сделка 25): $\text{Ind}$ = 8 %, маржа 5 % → 13 %, cap 10 % → ставка 10 %.

## 7. Субсидия

Субсидия — отдельный поток `stream = sub` с событиями `sub_payment` и `sub_repricing`; суммы со знаком сделки. База начисления — остаток тела $B$ (H4).

Ставка субсидии (H4):

$$r_{\text{sub}}(t) = \begin{cases} k \cdot \text{Ind}(t_{\text{fix}}) + s, & \text{FLOAT}, \\ s, & \text{FIXED}, \end{cases}$$

$k$ = `sub_coeff_index` (пусто → 1), $s$ = `sub_interest_rate`, затем `sub_floor` / `sub_cap`. Фиксинг, лаг и прогноз — как в §6. Для FIXED индикатор и коэффициент игнорируются (сделки 52, 54, Q20).

Даты: правило `sub_payment_rule_*` плюс $T_m$; начисление — с последней даты субсидии $\le T_0$, а если правило начинается после $T_0$ — с его начала (сделка 50: с 2022-11-01).

Пример (сделка 47): $k = 1$, $\text{Ind} = 8\%$, $s = 7{,}5\%$ → $r_{\text{sub}} = 15{,}5\%$; (сделка 53): $0{,}9 \cdot 8\% + 3{,}1\% = 10{,}3\%$.

**Справочно — возмещение по госпрограммам.** В программах льготного кредитования банку возмещают недополученный доход: $r_{\text{возм}} = \text{КС} + \text{уровень возмещения} - r_{\text{клиента}}$ (у некоторых программ — с коэффициентом к КС). Форма H4 «$k \cdot \text{КС} + s$» покрывает этот случай, если $s$ = уровень возмещения − ставка клиента; точную формулу подтвердят эксперты (Q3).

## 8. Выход

Формат 3 контракта. Одна строка — одно событие; строки сделки идут подряд, по `payment_dttm`, затем `event_order`.

Порядок событий в один день: `repricing` / `sub_repricing` → `interest_payment` → `sub_payment` → `principal_payment` → `close_payment`.

| Поле события | Значение |
|---|---|
| `amount` | сумма со знаком сделки; для `repricing` / `sub_repricing` — 0 |
| `principal_before` / `after` | остаток до / после события; после `close_payment` — строго 0 |
| `rate` | ставка последнего отрезка периода начисления; для пересмотра — новая ставка |
| `base_rate` | индикатор для FLOAT, иначе пусто |
| `accrual_start_dttm` / `end_dttm`, `accrual_days`, `year_frac` | для `interest_payment` / `sub_payment`: период $(a, b]$, дни $b - a$, $\tau(a, b)$ |

Суммы в файле округлены до 2 знаков; внутри расчёта округления нет. Ошибки — `errors.csv` (`deal_id,severity,code,field,message`): USD → `error CURRENCY_NOT_RUB`; расхождение графика → `warning PRINCIPAL_SUM_MISMATCH`; FLOAT без пересмотров → `warning FLOAT_NO_REPRICING`.
