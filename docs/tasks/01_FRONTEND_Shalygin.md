## Как использовать с Claude Code

1. Если репозиторий пустой: склонируй его, положи `00_CONTRACT.md` как `docs/CONTRACT.md` и первой дай Claude Code «Задачу F0» — она создаст скелет и запушит его в `main`.
2. Скопируй в Claude Code блок «Вводная для Claude Code» ниже, затем по одной задаче F1, F2… Не давай все сразу: после каждой задачи Claude Code сам сделает PR и смержит — ты смотришь отчёт и даёшь следующую.
3. Ветки, коммиты, PR и merge Claude Code делает сам по «Git-процессу» из вводной. Перед стартом выполни «Подготовку окружения» из docs/CONTRACT.md.

2. Коммить по ходу работы, добавляя только файлы своей зоны (git add <пути>), никогда git add -A / git add . по всему репо.

   Если конфликт в чужой зоне — остановись и сообщи мне.
6. git push -u origin <ветка>.
7. gh pr create --base main --title "<номер>: <кратко>" --body "<2–4 короткие строки: что сделано и как проверить>".

8. Дождись CI: gh pr checks --watch. Если упал — исправь в той же ветке, запушь, жди снова.
   Если для PR нет ни одной проверки — достаточно локальных проверок.
9. Когда всё зелёное: gh pr merge --squash --delete-branch --subject "<тот же короткий заголовок>".
10. git checkout main && git pull --ff-only. Отчитайся одной-двумя строками и дай ссылку на PR.
Запрещено: пушить напрямую в main, force-push в main, переписывать историю main, мержить с красным CI.

## F3. Слой данных: парсинг и валидация

```
В web/src/data/ сделай:
- types.ts — типы Deal и CashflowEvent по контракту (форматы 1 и 3), enum PaymentType, Stream.
- schemas.ts — zod-схемы строк; даты парсить из YYYY-MM-DD, числа из строки, пустое → null.
- parseCsv.ts — потоковый парсинг через papaparse в Web Worker (worker: true / свой worker),
  с прогрессом (0–100%) и сбором ошибок валидации {row, field, message}. Должно выдерживать 500 000 строк.
- store.ts — индекс событий по deal_id (Map<string, CashflowEvent[]>), сводка по сделке:
  число событий, сумма тела, сумма процентов (client), сумма субсидии (sub), последняя дата, итоговый остаток,
  флаг finalBalanceNonZero если |principal_after последнего события| > 0.005.
Тесты vitest: корректная строка, строка с ошибкой в дате, отрицательная сделка (депозит), пустые поля, порядок событий.
```
Приёмка: тесты проходят; парсинг файла из 500 000 строк не замораживает UI (проверить на сгенерированном файле).

## F6. Экран «Сверка» (главная фича для демо)

```
Экран сравнения результата калькулятора с эталоном:
- Загрузка двух наборов: «Результат движка» (один CSV) и «Эталон» (несколько файлов testdata/golden/deal_<id>.csv или один CSV).
- Сопоставление по ключу deal_id + payment_dttm + payment_type + stream; при дублях ключа — по порядковому номеру.
- Поле «Допуск», по умолчанию 0.01.
- Статусы строк: совпало / расхождение (|Δamount| или |Δprincipal_after| > допуска) / нет в движке / лишнее в движке.
- Сводка по сделкам: всего строк, совпало, расхождений, макс |Δ|. Сделка зелёная только если всё совпало.
- Таблица расхождений с колонками эталон / движок / Δ, подсветка.
- Экспорт отчёта сверки в CSV.
Логику сопоставления вынеси в web/src/compare/ и покрой тестами (совпадение, расхождение в 0.02, отсутствующая строка, лишняя строка).
```
Приёмка: если подсунуть эталон с изменённой на 1 копейку суммой, при допуске 0.01 — совпало, при допуске 0.005 — расхождение.

## F7. Генератор синтетического портфеля

```
Создай tools/gen-portfolio/ — Node + TypeScript CLI (tsx), без зависимостей кроме csv-stringify и commander.
Команда: npm run gen -- --n 1000000 --seed 42 --report-date 2022-08-31 --out ../../testdata/synthetic/deals_1m.csv
Генерирует сделки в формате 1 контракта, потоково (без хранения всех в памяти).
Распределение: 35% ANN, 30% RGM, 35% SIMPLE; 30% FLOAT (CBKEY1M), 10% с субсидией, 10% депозиты (отрицательный остаток);
суммы 50 000–20 000 000 (логнормально), срок 1–30 лет, периоды 1M/3M/ENDDATE, конвенции ACT/365 и ACT/ACT ISDA,
day_num 1–28 и -1. Детерминизм: один seed — один и тот же файл (используй seedable PRNG, напр. mulberry32).
Добавь testdata/synthetic/ в .gitignore. README с примерами.
```
Приёмка: 1 000 000 сделок генерируются меньше чем за минуту; два запуска с одним seed дают одинаковый sha256.
