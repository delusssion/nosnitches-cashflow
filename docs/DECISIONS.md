# Архитектурные решения

Кратко: дата · решение · почему.

## 2026-10-30 · Ядро расчёта на Rust

Требование эксперта: калькулятор должен работать на огромном числе сделок и экономно расходовать CPU. Ядро — cargo workspace в `engine/`, CLI `cfgen`.

## 2026-10-31 · Начисление процентов — по отрезкам между событиями

Платёж тела внутри процентного периода режет его на секции: каждая секция начисляется на остаток, действовавший в ней («начисление процентов по отрезкам между событиями» из задания). Если эталоны аналитика будут считать по остатку на начало периода целиком — меняется одним местом (`run_timeline` в `engine/crates/cfcore/src/engine/mod.rs`).

## 2026-10-31 · close_payment и хвост начисления

Последнее событие по телу — всегда `close_payment` на весь остаток: после него `principal_after = 0` строго. Перепокрытие явного графика (сделка 20) срезается — собирается ровно остаток; недобор (сделка 54) добирается в `close_payment` в дату погашения (H9). Если даты процентов не доходят до погашения, в дату close добавляется процентный платёж за хвост периода (сделка 55: проценты до 30.06, тело 04.07).

## 2026-10-31 · FLOAT до ветки engine/float

Ставка FLOAT замораживается на дате расчёта (H2+H3): значение индикатора берётся из истории не позже `report_dttm` (`RateSeries::fixing` не «подглядывает» фактические будущие ставки), плюс маржа `interest_rate`, затем floor/cap. События `repricing` появятся в ветке `engine/float`; ANN считается в `engine/ann` (сейчас заглушка — 0 событий).
